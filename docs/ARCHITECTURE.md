# Architecture

- `src/ui`: React renderer; no Node integration.
- `electron/preload.ts`: narrow, channel-allowlisted context bridge.
- `electron/main.ts`: IPC handlers, provider orchestration, streaming and mission events.
- `electron/providers.ts`: Anthropic Messages and OpenAI-compatible Chat Completions adapters.
- `electron/workspace.ts`: path-confined access to the folders assigned to a team (listing, file reads, WRITE/DELETE/MKDIR on writable folders, application launching gated by the team toggle, action-marker parsing).
- `electron/database.ts`: SQLite in the OS user-data directory (including the `settings` key/value table used for preferences such as the UI language).
- `electron/agents.ts`: built-in agent identity and prompts.
- `src/ui/i18n.ts`: French/English UI dictionaries; `useLang` (in `src/ui/hooks.ts`) resolves the stored choice, then the OS language, and persists changes.
- `build/`: electron-builder resources — `license.txt` (shown by the assisted NSIS installer), `installer.nsh` (NSIS customization), `installerHeader.bmp` and icons generated by `make-icons.py`.

The main process owns provider requests and secrets. Messages and team missions are persisted locally. Team execution currently sends each participant the original task plus previous participant output, sequentially. Filesystem access is restricted to the folders explicitly assigned to the team: reads are always available, writes require a folder flagged `[WRITABLE]` in the team settings, and launching applications requires the team-level toggle; all actions are marker-driven (READ/WRITE/DELETE/MKDIR/RUN/RUN_WAIT full lines) and executed only by the main process.
